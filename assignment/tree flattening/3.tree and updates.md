This is a **classic subtree range update + distinct count** problem on a tree.
Given your past questions, I’ll explain it **interview-ready**, with **intuition, algorithm, and why it works**, and then give **Java implementation + dry run idea**.

---

## Key Observations

1. The tree is **rooted at 1**
2. **Subtree queries** → can be converted to **range queries** using **Euler Tour (DFS time in / time out)**
3. Values are **small (1 to 60)** → perfect for **bitmask representation**
4. Two operations:

   * **Update entire subtree to one value**
   * **Query number of distinct values in subtree**

---

## Core Technique Used

### 🔥 Euler Tour + Segment Tree + Lazy Propagation + Bitmask

---

## Step 1: Convert Tree to Array (Euler Tour)

We do a DFS and assign each node a **time-in**.

```
DFS order:
tin[u] = time++;
flat[tin[u]] = u;
tout[u] = time - 1;
```

### Important Property

👉 **Subtree of node X** becomes:

```
range = [ tin[X] , tout[X] ]
```

---

## Step 2: Represent Values Using Bitmask

Since values are `1 to 60`, represent each value as:

```
value = v
mask = 1L << (v - 1)
```

Example:

```
value 1 → 0001
value 2 → 0010
value 3 → 0100
```

Distinct count = **number of set bits** (`Long.bitCount(mask)`)

---

## Step 3: Segment Tree Structure

Each segment tree node stores:

| Field  | Meaning                                                  |
| ------ | -------------------------------------------------------- |
| `mask` | OR of all values in this range                           |
| `lazy` | If not `-1`, means overwrite entire range with one value |

---

## Step 4: Operations

### ✅ Query Type 1: `1 X Y`

Update subtree of X → range `[tin[X], tout[X]]`

We:

* Create mask `1 << (Y - 1)`
* Overwrite segment using **lazy propagation**

---

### ✅ Query Type 2: `2 X F`

Ignore F
Query range `[tin[X], tout[X]]`

Answer:

```
Long.bitCount(resultMask)
```

---

## Time Complexity

| Operation | Complexity       |
| --------- | ---------------- |
| DFS       | O(N)             |
| Update    | O(log N)         |
| Query     | O(log N)         |
| Total     | O((N + Q) log N) |

✔ Works within constraints

## Java Implementation

```java
import java.util.*;

public class SubtreeDistinctValues {

    static int N, Q;
    static List<Integer>[] tree;
    static int[] tin, tout, flat;
    static int timer = 0;
    static long[] seg, lazy;

    static void dfs(int u, int parent) {
        tin[u] = timer;
        flat[timer] = u;
        timer++;

        for (int v : tree[u]) {
            if (v != parent) {
                dfs(v, u);
            }
        }
        tout[u] = timer - 1;
    }

    static void build(int idx, int l, int r, int[] A) {
        if (l == r) {
            int node = flat[l];
            seg[idx] = 1L << (A[node] - 1);
            return;
        }
        int mid = (l + r) / 2;
        build(2 * idx, l, mid, A);
        build(2 * idx + 1, mid + 1, r, A);
        seg[idx] = seg[2 * idx] | seg[2 * idx + 1];
    }

    static void push(int idx) {
        if (lazy[idx] != -1) {
            seg[2 * idx] = lazy[idx];
            seg[2 * idx + 1] = lazy[idx];
            lazy[2 * idx] = lazy[idx];
            lazy[2 * idx + 1] = lazy[idx];
            lazy[idx] = -1;
        }
    }

    static void update(int idx, int l, int r, int ql, int qr, long val) {
        if (ql > r || qr < l) return;
        if (ql <= l && r <= qr) {
            seg[idx] = val;
            lazy[idx] = val;
            return;
        }
        push(idx);
        int mid = (l + r) / 2;
        update(2 * idx, l, mid, ql, qr, val);
        update(2 * idx + 1, mid + 1, r, ql, qr, val);
        seg[idx] = seg[2 * idx] | seg[2 * idx + 1];
    }

    static long query(int idx, int l, int r, int ql, int qr) {
        if (ql > r || qr < l) return 0;
        if (ql <= l && r <= qr) return seg[idx];
        push(idx);
        int mid = (l + r) / 2;
        return query(2 * idx, l, mid, ql, qr)
             | query(2 * idx + 1, mid + 1, r, ql, qr);
    }

    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        N = sc.nextInt();
        Q = sc.nextInt();

        int[] A = new int[N + 1];
        for (int i = 1; i <= N; i++) A[i] = sc.nextInt();

        tree = new ArrayList[N + 1];
        for (int i = 1; i <= N; i++) tree[i] = new ArrayList<>();

        for (int i = 0; i < N - 1; i++) {
            int u = sc.nextInt();
            int v = sc.nextInt();
            tree[u].add(v);
            tree[v].add(u);
        }

        tin = new int[N + 1];
        tout = new int[N + 1];
        flat = new int[N];

        dfs(1, 0);

        seg = new long[4 * N];
        lazy = new long[4 * N];
        Arrays.fill(lazy, -1);

        build(1, 0, N - 1, A);

        while (Q-- > 0) {
            int type = sc.nextInt();
            int X = sc.nextInt();

            if (type == 1) {
                int Y = sc.nextInt();
                long mask = 1L << (Y - 1);
                update(1, 0, N - 1, tin[X], tout[X], mask);
            } else {
                sc.nextInt(); // F ignored
                long res = query(1, 0, N - 1, tin[X], tout[X]);
                System.out.println(Long.bitCount(res));
            }
        }
    }
}
```

# 1️⃣ Why BITMASK is used (Most Important Insight)

### Problem Requirement

For a subtree, we need:

> **Number of DISTINCT values**

Values range:

```
A[i], Y ∈ [1 … 60]
```

---

## ❌ Naive Approach (Why it fails)

Store a `Set<Integer>` in each segment tree node.

❌ Too slow
❌ Too much memory
❌ Merge sets every query → O(N)

---

## ✅ Bitmask = Perfect Fit

### Idea

Each possible value (1–60) gets **one bit** in a 64-bit number (`long`).

```
bit position = value - 1
```

### Example

| Values in subtree | Bitmask |
| ----------------- | ------- |
| {1, 3, 5}         | 10101   |
| {2}               | 00010   |
| {1, 2, 3}         | 00111   |

---

## 🔥 Key Advantages

| Operation            | Why Bitmask is Fast   |
| -------------------- | --------------------- |
| Merge                | `OR` operation (O(1)) |
| Update whole subtree | Set mask directly     |
| Distinct count       | `Long.bitCount()`     |
| Memory               | Just 8 bytes per node |

# 2️⃣ Why FLAT ARRAY is Needed (Tree → Array Conversion)

### Problem with Trees

Segment Tree works on **arrays**, not trees.

Tree subtree is **non-contiguous in memory**.

---

## ✅ Solution: Euler Tour (Flattening)

We perform DFS and assign **entry time**:

```
dfs(u):
   tin[u] = timer
   flat[timer] = u
   timer++
```

### What `flat[]` stores

```
flat[i] = node number whose DFS entry time is i
```

---

## Example Tree

```
        1
       / \
      2   3
     / \
    4   5
```

### DFS Order

```
Time:   0  1  2  3  4
Node:   1  2  4  5  3
```

### flat[] array

```
flat = [1, 2, 4, 5, 3]
```

---

## 🔑 Subtree Property (Golden Rule)

> **All nodes of subtree(X) appear contiguously in flat[]**

So:

```
subtree(X) = flat[tin[X] ... tout[X]]
```

---

## Interview Line 💡

> “Flattening converts subtree queries on a tree into range queries on an array.”

# 3️⃣ What Exactly is Stored in Segment Tree?

Each **segment tree node** stores:

```
seg[node] = OR of bitmasks of all nodes in this segment
```

---

## Leaf Node Meaning

```
Segment [i, i]
seg = bitmask of flat[i]'s value
```

Example:

```
flat[2] = node 4
A[4] = 3
seg = 1 << (3 - 1) = 100
```

---

## Internal Node Meaning

```
Segment [l, r]
seg = seg[left child] OR seg[right child]
```

---

## Visual Example

Assume values:

```
Node:  1  2  4  5  3
Value: 1  2  3  2  1
```

Bitmasks:

```
1 → 0001
2 → 0010
3 → 0100
```

Segment:

```
Range [1..3] → nodes {2,4,5}
Masks: 0010 | 0100 | 0010 = 0110
Distinct = 2
```

### Update Query

```

```


# Why do we write

```java
long mask = 1L << (Y - 1);
```

---

## 1️⃣ What a Bitmask Represents

We want **one bit per value**:

| Value | Bit position |
| ----- | ------------ |
| 1     | bit 0        |
| 2     | bit 1        |
| 3     | bit 2        |
| …     | …            |
| 60    | bit 59       |

So:

```
bit index = value - 1
```

That’s why we shift by `(Y - 1)`.

---

## 2️⃣ Why shift `1`?

Binary `1` is:

```
0000001
```

Left shift means:

```
1 << k  →  bit k becomes 1
```

Example:

```
1 << 3 = 0001000
```

This means:

> “Value (k + 1) is present”

---

## 3️⃣ Why `Y - 1` and NOT `Y`?

Because **bit positions are 0-based**, but **values are 1-based**.

| Value (Y) | Bit index |
| --------- | --------- |
| 1         | 0         |
| 2         | 1         |
| 3         | 2         |

So:

```java
1 << (Y - 1)
```

maps value `Y` → correct bit.

---

## 4️⃣ Why `1L` and not `1`?

### Critical Interview Point ⚠️

#### `1` is an `int` (32 bits)

```java
1 << 40   ❌ WRONG (overflow / undefined bits)
```

#### `1L` is a `long` (64 bits)

```java
1L << 59  ✅ SAFE
```

Since values go up to **60**, we **must use long**.

---

## 5️⃣ Concrete Examples

### Example 1

```java
Y = 1
mask = 1L << 0 = 0001
```

### Example 2

```java
Y = 3
mask = 1L << 2 = 0100
```

### Example 3 (subtree has {1, 3, 5})

```
mask = (1<<0) | (1<<2) | (1<<4)
     = 10101
```

---

## 6️⃣ How Distinct Count Works

After OR-ing masks:

```java
long res = mask1 | mask2 | mask3;
```

We count:

```java
Long.bitCount(res)
```

Each `1` bit = **one distinct value**

---

## 7️⃣ Why This Is Perfect for This Problem

| Requirement       | Bitmask Advantage   |
| ----------------- | ------------------- |
| Values ≤ 60       | Fits in 64-bit long |
| Distinct count    | O(1)                |
| Merge ranges      | OR operation        |
| Subtree overwrite | Single mask         |

---

## 8️⃣ Interview-Perfect Explanation 🎯

> “Since values range from 1 to 60, I use a 64-bit long bitmask. Each value Y maps to bit (Y−1). I use `1L` to avoid int overflow and shifting sets the presence bit for that value.”

---

## 9️⃣ One-Line Memory Trick 🧠

> **Value → Bit = (value − 1)**
> **Presence → bit = 1**

Great follow-up 👍
**Short answer:**
👉 **Yes, technically you *can* use `1L << Y`, but it is NOT recommended for this problem.**
Now let’s understand **why interviewers still expect `1L << (Y - 1)`**.

---

## 1️⃣ What `1L << Y` Does

```java
mask = 1L << Y;
```

This sets **bit index = Y**.

### Example

| Y | Bit set |
| - | ------- |
| 1 | bit 1   |
| 2 | bit 2   |
| 3 | bit 3   |

---

## 2️⃣ Problem: Values Are 1-Based, Bits Are 0-Based

### Value domain:

```
Values: 1 ... 60
```

### Bit positions:

```
Bits: 0 ... 63
```

If you use:

```java
1L << Y
```

Then:

* Value `1` → bit 1
* Value `60` → bit 60

Bit `0` is **wasted**.

---

## 3️⃣ Why This Is Considered Bad Practice

### ❌ Waste of bit 0

You unnecessarily lose one usable bit.

### ❌ Risky if constraints change

If tomorrow values become `≤ 64`:

```
1L << 64   ❌ invalid shift
```

### ❌ Confusing to readers/interviewers

Standard mapping is:

```
value → bit (value - 1)
```

---

## 4️⃣ Why `1L << (Y - 1)` Is the Correct Mapping

```java
mask = 1L << (Y - 1);
```

### Clean one-to-one mapping

| Value | Bit |
| ----- | --- |
| 1     | 0   |
| 2     | 1   |
| 60    | 59  |

✔ No wasted bits
✔ Safe within 64 bits
✔ Industry standard

---

## 5️⃣ When `1L << Y` Might Be Acceptable

Only if:

* You **explicitly document** it
* Values are **strictly < 63**
* You never use bit 0

Example:

```java
// Bit 0 unused intentionally
long mask = 1L << Y;
```

But in interviews, this raises questions ⚠️

---

## 6️⃣ Interview Verdict 🚨

| Expression      | Interview Verdict |
| --------------- | ----------------- |
| `1L << (Y - 1)` | ✅ Expected        |
| `1L << Y`       | ⚠️ Suspicious     |
| `1 << Y`        | ❌ Wrong           |
| `1L >> Y`       | ❌ Wrong           |

---

## 7️⃣ One-Line Interview Answer 🎯

> “Using `1L << Y` wastes bit 0 and is off-by-one. I prefer `1L << (Y - 1)` to map value 1 to bit 0 cleanly and stay within 64-bit limits.”

---

## 8️⃣ Golden Rule to Remember 🧠

> **If values start from 1 → use (value − 1) for bit index**
