This is a **classic tree + range update/query problem**, best solved using
**Euler Tour (DFS flattening) + Segment Tree with Lazy Propagation**.

I’ll explain **step-by-step**, with intuition, math, and a small dry run.

---

## 🔑 Key Observations

* Tree is **rooted at 1**
* Queries are always on **subtree of X excluding X**
* Initial value of **all nodes = 1**
* Operations:

  * Set entire subtree to **1**
  * Set entire subtree to **0**
  * Count number of **1s** in subtree

👉 Subtree operations scream **range operations** → convert tree into an array.

---

## Step 1️⃣ Convert Tree → Array (Euler Tour / DFS Order)

We run DFS and assign:

* `tin[u]` → time when node `u` is entered
* `tout[u]` → time when DFS exits `u`

During DFS, each node appears **once** in the array.

### Important Property

For any node `X`:

```
Subtree of X = range [tin[X], tout[X]]
```

Since the query **excludes X**, the required range is:

```
[tin[X] + 1, tout[X]]
```

## Step 2️⃣ Build Segment Tree on DFS Array

* Array size = `A`
* Initial value at every index = `1`
* Segment tree node stores:

  * `sum` → number of 1s in that range
* Lazy value:

  * `-1` → no pending update
  * `0` → set entire range to 0
  * `1` → set entire range to 1

---

## Step 3️⃣ Lazy Propagation Logic

### Range Update

If update range fully covers segment:

* Set `sum = (r - l + 1) * value`
* Mark lazy flag

### Range Query

* Return sum of the segment
* Push lazy values down when needed

---

## Step 4️⃣ Handling Each Query Type

Let:

```
l = tin[X] + 1
r = tout[X]
```

If `l > r`, subtree is empty → answer is 0.

### Query Type 1: `1 X`

Set subtree to **1**

```
update(l, r, 1)
```

### Query Type 2: `2 X`

Set subtree to **0**

```
update(l, r, 0)
```

### Query Type 3: `3 X`

Count number of 1s

```
query(l, r)
```

## 5️⃣ Why Lazy Propagation Is Needed

Without lazy propagation:

* Updating subtree = O(N)
* Q up to 2×10⁵ → TLE

With lazy propagation:

* Range update = **O(log N)**
* Query = **O(log N)**

Lazy value meanings:

```
-1 → no pending update
 0 → set entire segment to 0
 1 → set entire segment to 1
```

## 6️⃣ Java Implementation (Clean & Interview-Ready)

```java
import java.util.*;

public class TreeLazyPropagation {

    static List<Integer>[] tree;
    static int[] tin, tout;
    static int timer = 0;

    // Segment Tree
    static int[] seg;
    static int[] lazy;

    static void dfs(int u, int parent) {
        tin[u] = ++timer;
        for (int v : tree[u]) {
            if (v != parent) {
                dfs(v, u);
            }
        }
        tout[u] = timer;
    }

    static void build(int idx, int l, int r) {
        lazy[idx] = -1;
        if (l == r) {
            seg[idx] = 1; // initially all 1
            return;
        }
        int mid = (l + r) / 2;
        build(2 * idx, l, mid);
        build(2 * idx + 1, mid + 1, r);
        seg[idx] = seg[2 * idx] + seg[2 * idx + 1];
    }

    static void push(int idx, int l, int r) {
        if (lazy[idx] == -1) return;

        seg[idx] = (r - l + 1) * lazy[idx];

        if (l != r) {
            lazy[2 * idx] = lazy[idx];
            lazy[2 * idx + 1] = lazy[idx];
        }
        lazy[idx] = -1;
    }

    static void update(int idx, int l, int r, int ql, int qr, int val) {
        push(idx, l, r);

        if (r < ql || l > qr) return;

        if (ql <= l && r <= qr) {
            lazy[idx] = val;
            push(idx, l, r);
            return;
        }

        int mid = (l + r) / 2;
        update(2 * idx, l, mid, ql, qr, val);
        update(2 * idx + 1, mid + 1, r, ql, qr, val);
        seg[idx] = seg[2 * idx] + seg[2 * idx + 1];
    }

    static int query(int idx, int l, int r, int ql, int qr) {
        push(idx, l, r);

        if (r < ql || l > qr) return 0;

        if (ql <= l && r <= qr) {
            return seg[idx];
        }

        int mid = (l + r) / 2;
        return query(2 * idx, l, mid, ql, qr)
             + query(2 * idx + 1, mid + 1, r, ql, qr);
    }

    public static void main(String[] args) {
        int A = 5;

        tree = new ArrayList[A + 1];
        for (int i = 1; i <= A; i++) tree[i] = new ArrayList<>();

        // Tree edges
        tree[1].add(2); tree[2].add(1);
        tree[1].add(3); tree[3].add(1);
        tree[2].add(4); tree[4].add(2);
        tree[2].add(5); tree[5].add(2);

        tin = new int[A + 1];
        tout = new int[A + 1];

        dfs(1, 0);

        seg = new int[4 * A];
        lazy = new int[4 * A];

        build(1, 1, A);

        // Example queries
        System.out.println(query(1, 1, A, tin[1] + 1, tout[1])); // 4

        update(1, 1, A, tin[2] + 1, tout[2], 0);

        System.out.println(query(1, 1, A, tin[1] + 1, tout[1])); // 2
    }
}
```

# PART 1️⃣: Why do we use **0-based or 1-based indexing**?

## A) DFS / Euler Tour Indexing

In our code:

```java
tin[u] = ++timer;
```

We used **1-based indexing** for the flattened array:

```
Index:  1  2  3  4  5
Node:   1  2  4  5  3
```

### Why 1-based?

* Cleaner math: subtree range = `[tin[X]+1, tout[X]]`
* Segment tree root naturally becomes `[1, N]`
* Avoids confusion with `0` (unused index)

👉 **This is a choice**, not a requirement.

---

## B) Segment Tree Indexing (IMPORTANT)

### Segment tree array:

```java
seg[1] → root
seg[2] → left child
seg[3] → right child
```

Child relationships:

```text
left  = 2 * idx
right = 2 * idx + 1
```

### Why NOT 0-based segment tree indexing?

If we start at `0`:

```
left  = 2*i + 1
right = 2*i + 2
```

This works too, but:

* More error-prone
* Harder to visualize recursion
* 1-based is industry-standard for segment trees

📌 **Conclusion**

> 1-based indexing is chosen for simplicity and readability.

# PART 2️⃣: Why is segment tree size `4 * N`?

This is the **most common interview trap question**.

---

## A) Segment Tree Structure Recap

Segment tree is a **binary tree** built over an array of size `N`.

Each node stores info about a segment `[l, r]`.

---

## B) Worst-Case Size of Segment Tree

### If `N` is a power of 2:

```
Total nodes = 2*N - 1
```

Example:

```
N = 8
Nodes = 15
```

---

### If `N` is NOT a power of 2:

Segment tree becomes **unbalanced** internally.

Example:

```
N = 5
Next power of 2 = 8
Nodes ≈ 2*8 = 16
```

---

## C) Why `4 * N` Is Always Safe

For any `N`:

```
Max nodes ≤ 4 * N
```

This is a **mathematical upper bound**, not an exact count.

### Example: N = 5

```
Array indices: 1 2 3 4 5
Tree structure:

                      [1,5]
                /                  \
           [1,3]                    [4,5]
        /        \                /        \
     [1,2]      [3,3]          [4,4]      [5,5]
```

Count nodes:

```
≈ 9 nodes
4*N = 20 (safe)
```

---

## D) Why NOT `2 * N`?

Because when `N` is not power of 2:

* Tree nodes spill deeper
* Index jumps can exceed `2*N`

⚠️ Using `2*N` may cause **ArrayIndexOutOfBoundsException**.

---

## E) Why Not Dynamic Allocation?

Because:

* Recursion + pointers = slow
* Arrays are cache-friendly
* Competitive programming prefers arrays
